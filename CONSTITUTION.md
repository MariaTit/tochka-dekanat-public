
# CONSTITUTION — Конституция проекта «Точка»

## 1. Назначение проекта

«Точка» — конкурсный прототип цифрового деканата с личными кабинетами студента и сотрудника.

Главная цель — создать удобный, безопасный и действительно работающий веб-сервис.

Проект должен соответствовать конкурсному заданию и согласованному техническому заданию команды.

## 2. Приоритеты разработки

1. Работоспособность важнее количества функций.
2. Безопасность важнее визуальных эффектов.
3. Обязательные функции конкурса важнее дополнительных.
4. Простота и понятность важнее неоправданной сложности.
5. Каждая реализованная функция должна быть проверена.

Запрещено выдавать незавершённые функции за работающие.

## 3. Безопасность

- Каждый студент имеет доступ только к собственным данным.
- Права доступа проверяются на сервере.
- Скрытие кнопки не заменяет проверку прав.
- Пароли хранятся только в виде стойких защищённых хешей.
- Секретные ключи и пароли запрещено записывать в исходный код.
- Приватные данные недоступны после выхода из аккаунта.
- Загрузка и скачивание файлов должны быть защищены.

## 4. Данные

- Используются исключительно вымышленные данные.
- Реальные университетские аккаунты и закрытые базы не подключаются.
- Заявки, сообщения и другие изменения сохраняются на сервере.
- Данные не должны исчезать после обновления страницы или перезапуска приложения.
- Отсутствующие данные нельзя подменять ложными значениями.
- Демонстрационные документы должны быть обозначены как образцы.

## 5. Пользовательский интерфейс

- Интерфейс полностью русскоязычный.
- Все основные функции работают на экранах от 360 px.
- Навигация должна быть понятной без дополнительных инструкций.
- Все кнопки должны выполнять заявленные действия.
- Ошибки, загрузка и пустые состояния должны отображаться корректно.
- Внешний вид должен соответствовать единой дизайн-системе проекта.
- Сайт должен быть обозначен как конкурсный концепт.
- Официальные логотипы университетов запрещены.

## 6. Архитектура

- Используется согласованный технологический стек.
- Код делится на логические модули.
- Повторяющиеся элементы реализуются общими компонентами.
- Нельзя создавать несколько независимых механизмов для одного процесса.
- Важные проверки выполняются на сервере.
- Архитектура должна допускать дальнейшее расширение проекта.

## 7. Функциональность

Обязательное ядро:
- Авторизация и профиль.
- Расписание.
- Успеваемость.
- Документы и заявки.
- Уведомления.

Дополнительные модули:
- Умные обращения.
- Чат с учебным офисом.
- Пульс университета.
- Новости.

Антиплагиат и проверка академических работ исключены из проекта.

## 8. Надёжность

- После изменения кода проверяется затронутая функциональность.
- Ошибки должны обрабатываться без потери сохранённых данных.
- Запрещено создавать ложные сообщения об успешных действиях.
- Изменения не должны ломать ранее работающие функции.
- При обнаружении проблемы необходимо сообщить о ней пользователю.

## 9. Работа с ИИ

- Разработка выполняется небольшими логическими блоками.
- Codex следует инструкциям AGENTS.md.
- Не добавляет функции вне поставленной задачи.
- Не выполняет Git-коммиты самостоятельно.
- Может использовать терминал для разработки и тестирования.
- Перед потенциально опасными действиями запрашивает разрешение.
- После завершения блока сообщает результат и ограничения.

## 10. Изменение конституции

Конституция является основой проекта.

Изменения допускаются только после явного согласования с пользователем.

Новые технические решения не должны противоречить её принципам.
