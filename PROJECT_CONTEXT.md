
# ТОЧКА — цифровой деканат будущего

## О проекте
«Точка» — конкурсный веб-прототип цифрового деканата, объединяющий учебную информацию, документы и общение с учебным офисом.

Проект разрабатывается одним человеком с помощью Codex.

## Роли пользователей
1. Студент — использует личный кабинет.
2. Сотрудник — обрабатывает обращения студентов и управляет информацией.

## Обязательные функции
- Авторизация и профиль студента.
- Расписание занятий.
- Успеваемость и оценки.
- Заявки на документы и отслеживание статусов.
- Уведомления.

## Дополнительные функции
- Умные обращения — подбор услуги по запросу студента.
- Пульс университета — проблемы, предложения и отзывы.
- Чат с учебным офисом.
- Новости университета.

## Основные требования
- Адаптивный интерфейс от 360 px.
- Современный минималистичный дизайн.
- Сохранение данных на сервере.
- Разделение доступа студентов.
- Безопасное хранение паролей.
- Только вымышленные персональные данные.
- Минимум два тестовых студента и один сотрудник.
- Сайт доступен из России без VPN.
- Явная маркировка конкурсного прототипа.

## Технологии

- Frontend: React + Vite.
- Backend: Node.js + Express.
- База данных: SQLite.
- Стили: CSS, адаптивная вёрстка.
- Контроль версий: Git.
- Среда разработки: VS Code + Codex.
- Хостинг: будет выбран перед публикацией.

## Принципы архитектуры

- Frontend и backend разделены логически.
- Данные хранятся на сервере.
- Авторизация и проверка прав выполняются сервером.
- Используются повторно применяемые компоненты.
- Структура проекта должна быть понятной и простой для сопровождения.

Блок SQLite и авторизации завершён 20.11.2026:

- SQLite через встроенный `node:sqlite`; файл `server/data/tochka.sqlite` не пересоздаётся
  при запуске и исключён из Git. Структура меняется SQL-миграциями с учётом версий.
- Таблицы: `schema_migrations`, `roles`, `users`, `sessions`.
- Пароли хранятся как scrypt-хеши (N=131072, r=8, p=1, индивидуальная случайная соль).
- `express-session` использует SQLite-хранилище. Сессия действует 8 часов с момента
  входа, переживает перезапуск. Cookie: HttpOnly, SameSite=Lax, Secure в production.
- `npm.cmd --prefix server run setup` создаёт локальный `.env` со случайным
  SESSION_SECRET и три аккаунта: `student1`, `student2`, `staff`. Пароли выводятся
  только при создании, не сохраняются в документации и исходниках. Повторный setup
  не меняет существующие данные. Сброс паролей пока не реализован.
- Настройки загружаются из `server/.env`; переменные окружения процесса имеют приоритет.
  Пример без секретов находится в `server/.env.example`.
- API: `/api/auth/login`, `/api/auth/me`, `/api/auth/logout`, `/api/student`, `/api/staff`,
  `/api/users/:userId`. Оба вида пользователей имеют доступ только к своему профилю;
  доступ сотрудника к студентам в этом блоке не добавлялся.
- Сервер проверяет сессию, роль и владельца профиля; закрывает приватные ответы
  от кеширования, ограничивает попытки входа и защищает изменяющие запросы от чужих сайтов.
- React проверяет сессию при загрузке, возврате на вкладку и раз в минуту.
  Студент открывает `/student`, сотрудник — `/staff`; токены в localStorage не хранятся.
- `npm.cmd --prefix server test` проверяет API на отдельных базах в `.cache/`.
- В Edge проверены три аккаунта, вход/выход, обновление страницы, перезапуск backend,
  ошибки, переход клавишей Tab и ширина 360 px. Предыдущее ограничение проверки Edge
  в текущем блоке не повторилось.
