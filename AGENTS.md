
# Проект «Точка»

Конкурсный прототип цифрового деканата с кабинетами студента и сотрудника.

## Правила работы

1. Пользователь — новичок в программировании. Объясняй свои действия простым русским языком.
2. Выполняй только задачи текущего запроса. Не добавляй функции по собственной инициативе.
3. Используй терминал для необходимых команд: установки зависимостей, запуска приложения, тестирования и диагностики.
4. Не выполняй Git-коммиты — пользователь делает их самостоятельно.
5. Перед удалением файлов, сбросом данных и другими потенциально опасными действиями запрашивай разрешение.
6. После изменений проверяй работоспособность затронутых функций.
7. Соблюдай требования безопасности и используй только вымышленные персональные данные.
8. Не записывай пароли, токены и секретные ключи в исходный код.
9. После завершения логического блока обновляй PROJECT_CONTEXT.md и PROGRESS.md, если они существуют.
10. В конце задачи кратко сообщай, какие файлы изменены, что проверено и какие проблемы остались.
11. Общайся с пользователем на русском языке.


## Организация работы

После каждого логического блока пользователь начинает новый чат Codex для экономии токенов.

Перед началом работы в каждом новом чате:
1. Прочитай AGENTS.md.
2. Прочитай CONSTITUTION.md.
3. Прочитай CONVENTIONS.md.
4. Прочитай PROJECT_CONTEXT.md.
5. Прочитай PROGRESS.md, если он существует.

Используй эти документы как постоянный контекст проекта.

Приоритет правил:
1. Текущие явные указания пользователя.
2. CONSTITUTION.md — основные принципы проекта.
3. CONVENTIONS.md — технические правила.
4. PROJECT_CONTEXT.md — описание проекта и архитектуры.
5. PROGRESS.md — фактическое состояние разработки.

Если обнаружено противоречие между документами, сообщи пользователю и запроси решение.

Не считай запланированные функции реализованными без проверки.

Не перечитывай большие документы повторно в рамках одной задачи без необходимости.

После завершения логического блока кратко обнови PROGRESS.md и при необходимости PROJECT_CONTEXT.md.
